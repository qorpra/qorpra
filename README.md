## The Qorpra Ecosystem

### Qorpix — The Language

**One language. Endless possibilities.**

Qorpix is our vision for a high-performance, extensible programming language capable of spanning the entire software stack.

From web applications and cloud infrastructure to native desktop software, mobile platforms, embedded systems, and operating systems.

Our goal is to make the boundaries between these domains smaller — and eventually, invisible.

### Qorpix Grammar (QG) — Define the Language

**A language should be extensible by design, not by exception.**

Qorpix Grammar is a declarative grammar and compiler-definition system designed to describe how programming languages are parsed, analyzed, extended, and compiled.

Its architecture is built around:

- **Grammar-driven compilation** — Define syntax and semantics through `.qg` specifications.
- **Self-hosting** — Enable the grammar system to compile its own language definitions.
- **Extensibility** — Introduce new language features without rewriting the compiler.
- **Typed semantic analysis** — Move beyond parsing into structured, verifiable meaning.
- **Native compilation** — Bridge verified intermediate representations to native machine-code generation.

QG is designed not only for Qorpix, but as a foundation for defining other languages and domain-specific programming models.

### [Qorpix Bootstrap](https://github.com/qorpra/qorpix-bootstrap) — The Foundation

**Every great system starts somewhere. Ours starts close to the machine.**

QB is the low-level bootstrap foundation of the Qorpix compiler architecture.

Designed with precise control over code generation, platform targets, and native execution, QB provides the path toward a compiler ecosystem built on its own infrastructure.

Our long-term goal is to control the compilation pipeline from source code to machine instructions, without relying on LLVM as the primary compiler backend.

## Built from First Principles

We believe powerful developer tools should be built on strong architectural foundations.

| Principle | Our Direction |
|---|---|
| **Performance** | Native-first compilation and efficient execution |
| **Extensibility** | Languages and features that evolve without rigid compiler boundaries |
| **Safety** | Explicit contracts, verified representations, and controlled execution |
| **Portability** | A common language architecture across multiple targets and platforms |
| **Independence** | Greater control over the compiler, runtime, and execution stack |
| **Transparency** | Engineering decisions validated through reproducible tests and real results |
| **Simplicity** | Make complex systems approachable without hiding their capabilities |

We believe simplicity and power should reinforce each other, not compete.
